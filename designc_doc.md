# SYSTEM DESIGN DOCUMENT: Интеллектуальный сервис обоснования НМЦК (Tender Hack — Пермь 2026)

## Архитектурный паттерн: Изолированные микросервисы (2 репозитория)
Решение разделено на два независимых сервиса для изоляции тяжелых вычислений (CPU/ML-bound) от асинхронной бизнес-логики (I/O-bound). Взаимодействие происходит по внутреннему REST API внутри сети Docker.

---

## ЧАСТЬ 1. BACKEND SERVICE (Репозиторий: `tender-backend`)

**Зона ответственности:** Оркестрация бизнес-логики, управление реляционной и векторной базой данных, фильтрация данных (по региону, дате), математический расчет НМЦК (по формуле организаторов), генерация итоговых документов (.docx), предоставление публичного API.

### 1.1. Технологический стек
*   **Язык:** Python 3.12
*   **Веб-фреймворк:** FastAPI + Pydantic v2
*   **СУБД:** PostgreSQL 16+ с расширением `pgvector` (для хранения эмбеддингов и быстрого косинусного поиска)
*   **ORM:** SQLAlchemy 2.0 (асинхронный движок `asyncpg`)
*   **Обработка данных:** `Polars` (высокопроизводительные DataFrame для агрегации цен)
*   **Генерация отчетов:** `python-docx`, `Jinja2` (шаблонизация)
*   **HTTP-клиент:** `httpx` (для асинхронных вызовов ML-сервиса)
*   **Менеджер пакетов:** `uv`

### 1.2. Схема базы данных (Связь с исходным датасетом)

**Таблица `ste_catalog` (Справочник СТЕ - на основе 2-го скриншота):**
*   `id` (UUID, Primary Key)
*   `ste_id` (String/Integer, маппинг на колонку `Идентификатор` [например, 34863000])
*   `name` (String, маппинг на `Наименование СТЕ` [например, "Мусорные пакеты 35л"])
*   `category` (String, маппинг на `Категория`[например, "Пакеты полимерные..."])
*   `manufacturer` (String, маппинг на `Производитель`)
*   `raw_characteristics` (Text, маппинг на `характеристики СТЕ`[сырая строка: "Количество в упаковке:30.00000;..."])
*   `parsed_characteristics` (JSONB, распарсенный ML-сервисом словарь признаков)
*   `embedding` (Vector(768) или Vector(256), векторное представление названия и характеристик. Индекс: HNSW)

**Таблица `contracts` (Исторические данные закупок - на основе 1-го скриншота):**
*   `id` (UUID, Primary Key)
*   `purchase_name` (String, маппинг на `Наименование закупки`)
*   `quantity` (Numeric, маппинг на `Количество`)
*   `unit` (String, маппинг на `Единица измерения` [например, "шт"])
*   `contract_identifier` (String, маппинг на `Идентификатор` [например, 204746787])
*   `purchase_method` (String, маппинг на `Способ закупки`[например, "Контракт по итогам..."])
*   `initial_cost` (Numeric, маппинг на `Начальная Стоимость`)
*   `discount_percent` (Numeric, маппинг на `% снижения`)
*   `vat_rate` (String, маппинг на `Ставка НДС`[например, "20%"])
*   `contract_date` (DateTime, маппинг на `Дата заключения контракта`)
*   `customer_inn` (String, маппинг на `ИНН заказчика`)
*   `customer_region` (String, маппинг на `Регион заказчика`[например, "Москва", "Пермский"])
*   `supplier_inn` (String, маппинг на `ИНН поставщика`)
*   `supplier_region` (String, маппинг на `Регион поставщика`)
*   `ste_id` (String, Foreign Key -> `ste_catalog.ste_id`, маппинг на `Идентификатор позиции`[например, 35927039])
*   `ste_name` (String, маппинг на `Наименование позиции` [например, "Холодильник Haier..."])
*   `price_per_unit` (Numeric, маппинг на `Цена за единицу` - **целевая переменная для расчета**)

### 1.3. REST API Эндпоинты (Публичные, для UI)

*   `GET /api/v1/ste/search`
    *   **Вход:** `query` (строка), `region` (строка, опц.), `months_depth` (int, ограничение давности, по умолчанию 12).
    *   **Логика:** Вызов ML-сервиса для получения вектора запроса -> SQL-запрос в `ste_catalog` через `<=>` (расстояние) с JOIN `contracts` -> фильтрация старых дат (сравнение `contract_date` и текущей) и региона.
    *   **Выход:** Список СТЕ-аналогов, их характеристики и массив исторических цен `price_per_unit`.
*   `POST /api/v1/nmck/calculate`
    *   **Вход:** Массив объектов с выбранными контрактами (ID, цена, дата).
    *   **Логика:** Отправка массива цен в ML-сервис (на эндпоинт детекции аномалий) -> получение "чистого" массива -> агрегация Polars -> применение формулы НМЦК.
    *   **Выход:** Итоговая сумма НМЦК, список отброшенных выбросов, коэффициенты (v — коэффициент вариации и т.д.).
*   `POST /api/v1/nmck/report`
    *   **Вход:** Данные успешного расчета НМЦК.
    *   **Логика:** Рендер шаблона `python-docx` с вставкой таблицы выбранных аналогов и итоговой цены.
    *   **Выход:** Файл `nmck_report.docx` (application/vnd.openxmlformats-officedocument.wordprocessingml.document).

## ЧАСТЬ 2. ML SERVICE (Репозиторий: `tender-ml-worker`)

**Зона ответственности:** Изолированное выполнение ML-моделей строго на CPU. Семантическая векторизация текста, интеллектуальный парсинг грязных строк в JSON с помощью локальных SLM (Small Language Models), выявление ценовых аномалий. Внешнего доступа нет.

### 2.1. Технологический стек
*   **Язык:** Python 3.12
*   **Микрофреймворк:** FastAPI (только для внутренних роутов)
*   **Инференс Эмбеддингов (Векторизация):** `onnxruntime` (CPU) + `huggingface_hub`
*   **Инференс SLM (Парсинг характеристик):** `llama-cpp-python` (CPU-инференс, поддержка квантования GGUF, поддержка строгих JSON-грамматик)
*   **Машинное обучение (Детекция выбросов):** `scikit-learn`, `numpy`
*   **Менеджер пакетов:** `uv`

### 2.2. ML-Модели (Локальные, под ограничения хакатона)
1.  **Semantic Search Model:** Локальная модель от Сбера (`sberbank-ai/ru-sentence-ruBERT` или актуальный легковесный `GigaEmbeddings`). Экспортируется в формат `.onnx` для максимальной скорости на процессоре без GPU.
2.  **Data Normalization Model:** Квантованная SLM (Small Language Model) архитектуры **GigaChat-Nano** или аналог (до 2 млрд параметров, формат `.gguf`, квантование Q4_K_M, вес ~1.5 ГБ). Используется исключительно для перевода строки характеристик СТЕ в структурированный JSONB.
3.  **Anomaly Detection Model:** Алгоритм `IsolationForest` (Изолирующий лес) из `scikit-learn`. Применяется динамически (fit_predict) на выборке цен конкретного товара для отсечения демпинга или завышений.

### 2.3. Внутренние API Эндпоинты (Вызываются только Бэкендом)

*   `POST /internal/ml/embed`
    *   **Вход:** `{"text": "Пакеты для мусора 35л"}`
    *   **Логика:** Токенизация и проход через ONNX-модель эмбеддингов.
    *   **Выход:** `{"embedding":[0.015, -0.042, 0.113, ...]}`
*   `POST /internal/ml/parse-characteristics`
    *   **Вход:** `{"raw_text": "Количество в упаковке:30.00000;Толщина, мкм:50.00000;Объем:35.00000"}`
    *   **Логика:** Запуск llama.cpp с GGUF-моделью. Промпт: извлечь пары ключ-значение. Использование grammar-форсирования для гарантии ответа строго в формате JSON без галлюцинаций.
    *   **Выход:** `{"parsed": {"Количество в упаковке": 30.0, "Толщина, мкм": 50.0, "Объем": 35.0}}`
*   `POST /internal/ml/detect-outliers`
    *   **Вход:** `{"prices":[23760.0, 24000.0, 23500.0, 1500.0, 95000.0]}` (пример холодильника Haier)
    *   **Логика:** Преобразование в numpy-массив `reshape(-1, 1)`, применение `IsolationForest(contamination=0.15)`.
    *   **Выход:** `{"valid_prices":[23760.0, 24000.0, 23500.0], "outliers": [1500.0, 95000.0]}`

## ЧАСТЬ 3. ИНФРАСТРУКТУРА (Deployment)

Единый файл `docker-compose.yml` для локального развертывания на серверах жюри.

```yaml
version: '3.8'

services:
  database:
    image: ankane/pgvector:latest
    container_name: tender_db
    environment:
      POSTGRES_USER: tender_user
      POSTGRES_PASSWORD: tender_password
      POSTGRES_DB: tenderhack_db
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  backend:
    build: 
      context: ./tender-backend
      dockerfile: Dockerfile
    container_name: tender_backend
    depends_on:
      - database
      - ml_worker
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql+asyncpg://tender_user:tender_password@database:5432/tenderhack_db
      - ML_SERVICE_URL=http://ml_worker:8001

  ml_worker:
    build: 
      context: ./tender-ml-worker
      dockerfile: Dockerfile
    container_name: tender_ml_worker
    expose:
      - "8001"
    volumes:
      - ./model_weights:/app/models # Оффлайн веса моделей (.onnx, .gguf)
    # Ресурсоемкий контейнер, без проброса внешних портов

volumes:
  pgdata:
```
